# Cipher Lab · 密码实验室

一个可交互的密码学实验台，包含 **口令图片加密** 和 **视觉秘密分享** 两个实验。前者可以生成加密文件、交给别人并用口令还原；后者把秘密拆成两份图像，直观看到秘密分享中的随机性和门限。

项目面向密码学学习和演示，重点是让安全性质有可观察的证据，也把实验指标为什么变化或不变化解释清楚。

## 两个实验

### 口令图片加密

- 将图片转换为 RGB 像素，再使用 Scrypt 从口令派生 AES-256 密钥。
- 使用 AES-256-GCM 加密并认证像素，生成 `.vclab` 文件。
- 下载文件后，可在“解密图片”页上传并用同一口令还原成 PNG。
- 改动密文或输入错误口令时，认证会失败，不会把损坏内容当作图片输出。
- 面板对比**同一批 RGB 字节**加密前后的熵、相邻字节相关性和直方图，并显示密文 SHA-256 指纹。

图片最多 10 MiB、800 万像素。为了便于还原，加密包会公开图像宽高；图片中的 RGB 像素由认证加密保护。输入图片的 EXIF 元数据不会保留，透明区域会先合成到白色背景。

加密使用独立随机盐和 96-bit nonce；口令不会写入文件。AES-GCM 负责机密性和认证，Scrypt 的计算与内存成本可调。可查看 [AES-GCM API 文档](https://cryptography.io/en/latest/hazmat/primitives/aead/) 和 [Scrypt API 文档](https://cryptography.io/en/latest/hazmat/primitives/key-derivation-functions/#scrypt)。

### 视觉秘密分享

- 上传图片或使用钥匙孔、星星、笑脸、爱心内置图案。
- 调整黑白阈值并随机生成两份 Share；分别下载或导出份额包。
- 切换单份视角，观察两份分别看起来像噪声；对齐叠加后才显现秘密。
- 查看原图熵、份额熵、像素比例、相邻像素相关性和对比度。

每个输入像素扩展成 2×2 子像素块。黑白秘密对应的两份图案关系不同，但单份的边缘分布相同。叠加时，白色秘密留下两个白点，黑色秘密变成全黑，因此理想对比度 α 为 0.5。

## 为什么 Share 熵一直是 1 bit？

这是方案的预期结果，不是图片没变化。这里的熵按二值图像的黑白频率计算。每个 2×2 Share 子块精确含有两个黑点和两个白点，所以整份 Share 的白点概率固定为 `p = 0.5`，二元熵 `H(p) = 1 bit`。份额均衡差也固定为 0%，因为构造本身保证了均衡。

会随图案变化的是**原图熵**和原图黑白比例。它们描述秘密图案本身，不是“加密强度评分”。视觉秘密分享页将固定的方案属性与变化的图像属性分开显示。若要观察传统“加密前后字节分布”如何变化，请用图片加密实验。

## 本地运行

需要 Python 3.10 或更新版本。

```bash
python -m venv .venv
```

Windows PowerShell：

```powershell
.venv\Scripts\Activate.ps1
```

macOS / Linux：

```bash
source .venv/bin/activate
```

安装依赖并启动：

```bash
python -m pip install -r requirements.txt
streamlit run app.py
```

## 项目结构

```text
app.py                  双实验室界面、交互和统计可视化
secure_image_crypto.py  口令派生、AES-GCM 容器与图像还原
vc_core.py              视觉秘密分享、图像预处理和统计指标
requirements.txt        Python 依赖
.streamlit/config.toml  深色主题和上传限制
```

## 复试展示时可以讨论

1. 为什么视觉秘密分享的单份熵应当保持不变？这和完美保密的边缘分布有什么关系？
2. AES-GCM 的认证标签如何帮助发现错误口令或密文篡改？
3. Scrypt 的内存成本如何影响口令猜测攻击和用户体验？
4. 为什么加密还需要 nonce？为什么相同密钥下不能重复使用 nonce？
5. 视觉秘密分享的对比度与像素扩展率之间有什么取舍？

本项目不上传图片到外部 API，也不会把数据写入磁盘。**若部署到公网，图片和口令会由部署该应用的服务器处理；请只在可信环境中使用。**
